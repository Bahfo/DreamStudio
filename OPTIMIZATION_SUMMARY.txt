1. CLOSING/EXIT ISSUES - FIXED
================================================================================

Problem:
- App window closes visually but Python process doesn't terminate
- Watchdog background threads keep the app alive

Files Modified:
- editor/ui_build.py (lines 780-806)
- backend/watcher/core.py (lines 104-159)

Solution:
- Added WM_DELETE_WINDOW protocol handler in ui_build.py
- Added _cleanup() method that properly stops all resources:
  * Closes all tabs
  * Destroys shell frame if open
  * Stops treeView watcher
  
- In core.py WatchDog class:
  * Added _stop_event = Event() flag for threads
  * Modified debouncer_worker and looping to check the flag
  * Added timeout-based joins to prevent hanging
  * Made threads daemon=True

Closing Flow:
1. User clicks close button
2. on_close() calls _cleanup()
3. _cleanup() stops watchdog, destroys widgets, calls window.quit()
4. After 0.5s delay, os._exit(0) force kills if still hanging

2. STARTUP PERFORMANCE - OPTIMIZED
================================================================================

Problem:
- Application takes long time to load and render
- Heavy synchronous operations during __init__

Optimizations Applied:

A. Lazy Icon Loading (icons_utils.py)
---------------------------------
BEFORE: 35+ PIL images loaded at module import time
AFTER:  Images load on-demand with caching

Changes:
- Replaced eager Image.open() calls with lazy get_icon(name) function
- Added _ICON_CACHE dictionary for caching loaded images
- Added has_icon(name) for checking icon existence
- Images only load when first needed

B. Deferred FileTree Population (treeview.py)
-----------------------------------------
BEFORE: populate_tree() called immediately in __init__
AFTER:  Population deferred, no WatchDog until user interaction

Changes:
- Added flags: _tree_populated, _watchdog_started (default False)
- Removed auto-populate in FileTree.__init__
- populate_tree() only runs when called explicitly
- _ensure_watcher_started() starts WatchDog lazily

C. Deferred App Initialization (ui_build.py)
----------------------------------------
BEFORE: All initialization in App.__init__ before window appears
AFTER:  Heavy operations deferred to after window exists

Changes:
- Added _deferred_init() called via window.after(100ms, ...)
- Tree population happens after window appears (faster perceived startup)
- Added _on_tree_interaction() for lazy WatchDog start

D. Lazy File Loading in TextEditor (texteditor/__init__.py)
-----------------------------------------------------
BEFORE: load_file() called immediately in __init__
AFTER:  load_file() called via after_idle() callback

Changes:
- Added _file_loaded flag
- File loads after idle event (UI renders first)

4. STARTUP FLOW (OPTIMIZED)
================================================================================

BEFORE (Slow):
1. App.__init__() starts
2. Load ~35 icons (blocking)
3. Create Config/Style objects
4. Build menus and toolbar
5. Load FileTree + populate + start WatchDog (3 threads)
6. Create TextEditors + load files
7. Window appears (SLOW)

AFTER (Fast):
1. App.__init__() starts
2. Window appears IMMEDIATELY (minimal UI)
3. 100ms later: _deferred_init() runs
4. Tree populates (scandir only, fast)
5. User expands folder -> WatchDog starts
6. User opens file -> File loads

Expected Improvement: 80-90% faster cold start
