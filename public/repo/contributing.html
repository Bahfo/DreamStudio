DreamStudio IDE Open Source Contributor Policy

Version 1.1.0+ Standard Policy | Effective Date: 2026
Preamble: Thank you for your interest in contributing to the DreamStudio IDE open-source repository. All contributors are required to adhere to the terms, hierarchy preferences, and commit message standards established below.
ARTICLE I: CLASSIFICATION AND PRIORITY OF CONTRIBUTIONS

Contributions submitted to the DreamStudio IDE repository are prioritized according to the following strict order of preference (Rank 1 being most preferred):

  1. Bug Fixes (Rank 1 - Highest Priority): The majority of accepted contributions consist of resolutions for verified, reproducible issues. Automated tests verifying the fix must accompany pull requests whenever feasible.
  2. Feature Additions (Rank 2 - By Prior Agreement Only): New functionality or feature proposals must receive explicit prior authorization from the maintainers. Submissions will be accepted solely when aligned with the strategic subsystem roadmap.
  3. Documentation Improvements (Rank 3): Documentation contributions must be thorough, sufficient in scope, and clearly articulate technical concepts and operational paradigms.
  4. Codebase Maintenance (Rank 4 - Lowest Priority): Routine refactoring or code maintenance contributions are generally discouraged, except when submitted in conjunction with a major release cycle.
ARTICLE II: COMMIT MESSAGE SPECIFICATION

Effective as of Version 1.1.0 and forward, all commits submitted to the repository must strictly conform to the standard structure outlined below:

1. Standard Commit Message Syntax
<Personal ID> <Commit Title>
<Fix Number (Given within the issued Personal ID Ticket)>
<description>
...
<End of commit message (Optional)>
2. Exemplar Structure
DS110-12345 Bahfo: Fixing Bug in Type Declaration
Number: 12345678
Fixed a smaller issue when opening a code-editor in language X and type of token Y didn't declare correctly. 

Thanks!
ARTICLE III: PROHIBITIONS AND DISCUSSION SUMMARIZATION
1. Restriction on External Reference Links

Contributors are strictly prohibited from embedding hyperlinks to external discussion threads, forum posts, or third-party chat logs within commit messages.

2. Mandate for In-Line Summarization

Where a commit relies on prior discussions or technical deliberations, the contributor must synthesize and summarize the essential details directly within the body of the commit message itself.
